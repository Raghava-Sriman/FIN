## 1. The Executive Manifesto

### What is "AI Slop" UI?
AI Slop is the visual signature of unprompted, unrefined frontend code generated by generic LLMs. It is immediately recognizable by:
- Over-saturated purple-to-blue linear gradients on every button and background.
- Massive, cartoonish border-radii (`rounded-3xl` or `rounded-full` on large cards).
- Excessive, floaty drop shadows (`shadow-2xl` with heavy black opacity).
- Ubiquitous emoji pollution (🚀, 💡, 🔥, ✨, 💰, 🤖) substituting for thoughtful iconography.
- Em dashes (`—`) and wandering single-asterisk markdown (`*word*`) cluttering copy.
- Awkward mobile layouts where titles wrap across three lines and primary buttons drop onto separate rows.
- Unformatted raw numbers (`₹41883.67382` or `$12450.0`).
- Low information density: huge empty cards with tiny amounts of data, forcing endless scrolling.

### The Institutional Standard (Stripe / Mercury / Linear)
The institutional aesthetic communicates **trust, precision, mathematical clarity, and utilitarian efficiency**:
- **Tactile Restraint**: Off-white and subtle slate surfaces (`#F9FAFB` canvas, pure `#FFFFFF` cards).
- **Hairline Precision**: 1px borders using muted slate shades (`#E2E8F0` / `#E5E7EB`). Never borderless floating cards.
- **High Information Density**: Compact typography, micro-labels (`text-[10px]` uppercase), and structured data strips.
- **Micro-Interactions Over Flash**: Crisp 150ms transitions, subtle hover border shifts, zero distracting bouncy animations.
- **Strict Number Formatting**: Financial figures are always formatted with commas, exact currency symbols, uniform font weights, and rounded integers for high-level summaries.

## 3. Typography & Number Formatting Standard

### 3.1 Typographic Scale

Use the `Inter` font family exclusively. Apply strict tracking and leading pairings:

| Class | Font Size | Tracking | Weight | Role |
| :--- | :--- | :--- | :--- | :--- |
| `text-[10px]` | 10px | `uppercase tracking-wider` | `font-bold` | Micro-labels, column headers, presets label |
| `text-[11px]` | 11px | `tracking-tight` | `font-semibold` | Metadata badges, table cell subtext, secondary indicators |
| `text-xs` | 12px | `normal` | `font-medium` | Standard table cell data, body descriptions, form labels |
| `text-sm` | 14px | `normal` | `font-medium` / `font-bold` | Navigation tabs, input text, card sub-headers |
| `text-base` | 16px | `tracking-tight` | `font-bold` | Modal titles, sub-section headers |
| `text-xl` | 20px | `tracking-tight` | `font-extrabold` | Section titles, secondary metrics |
| `text-2xl` sm: `text-3xl` | 24px - 30px | `tracking-tight` | `font-extrabold` | Primary KPI ribbon numbers |

### 3.2 The Strict Number Formatting Rules

Financial numbers are the centerpiece of the application. They must be rendered consistently:

1. **Exact Currency Prefix**: Always prefix values with the target currency symbol without an awkward floating space: `₹41,884` (not `Rs. 41884` or `₹ 41,884.00`).
2. **Indian Number System Grouping**: Format numbers with locale commas:
   ```typescript
   // Helper function for UI components
   export const formatINR = (val: number): string => {
     return `₹${Number(Math.round(val)).toLocaleString("en-IN")}`;
   };
   // Example: formatINR(2500000) => "₹25,00,000"
   ```
3. **No Awkward Float Pennies**: Strip dangling cents/pennies on high-value numbers (`₹41,884` instead of `₹41,883.673`). Only retain decimals for percentages (`7.5%`, `12.4%`).
4. **Number Weight Uniformity**: All financial figures and percentages inside prose or tables must have `font-semibold` or `font-extrabold` weight and `text-slate-900` color to stand out from descriptive body copy.
5. **Signed Inflows and Outflows**:
   - Inflows: `+₹10,042` in `text-emerald-600`
   - Outflows / Expenses: `-₹58,926` in `text-slate-900` or `text-rose-600` (if exceeding budget)

## 5. Mobile-First Responsive Engineering

Mobile optimization in an institutional app is not an afterthought. It dictates the architecture:

### 5.1 The Single-Row Mobile Header Rule

**Rule**: Page headers and their corresponding primary action buttons MUST stay on a **single row** on mobile devices. Never allow the button to drop below the title, consuming critical vertical screen real estate.

```tsx
/* Correct Single-Row Mobile Header */
<div className="flex items-center justify-between gap-2.5 sm:gap-4 min-w-0">
  <div className="flex items-center space-x-2 min-w-0">
    <h2 className="text-lg sm:text-xl font-bold text-slate-900 truncate">
      Goal Planner
    </h2>
    <span className="hidden sm:inline-flex px-2 py-0.5 rounded-full bg-slate-100 text-slate-700 text-xs font-bold shrink-0">
      {goals.length}
    </span>
  </div>

  <button
    onClick={() => setShowModal(true)}
    className="inline-flex items-center space-x-1.5 px-3 py-1.5 rounded-lg bg-slate-900 text-white text-xs font-semibold hover:bg-slate-800 transition cursor-pointer shrink-0 shadow-xs"
  >
    <Plus className="w-3.5 h-3.5" />
    <span className="whitespace-nowrap">Create Goal</span>
  </button>
</div>
```

### 5.2 The 3-Column Mobile Data Strip Pattern

Wide desktop table rows fail on mobile screens. Instead of horizontal table scrolling for card lists (such as statements or policies), transform the row into a **3-column mobile data strip**:

## 7. The AI Agent & Conversational UX Standard

When incorporating an AI assistant (like **Finneas** in FinSight), the interface must maintain fiduciary authority.

### 7.1 The Three Hard Output Negatives

Before rendering any model output to the DOM, enforce this strict pipeline:

```typescript
export const cleanInstitutionalText = (raw: string): string => {
  let clean = raw || "";

  // 1. RULE 1: Strip ALL unicode emojis, flags, symbols, and pictographs
  clean = clean.replace(
    /[\u{1F600}-\u{1F64F}\u{1F300}-\u{1F5FF}\u{1F680}-\u{1F6FF}\u{1F1E0}-\u{1F1FF}\u{2702}-\u{27B0}\u{24C2}-\u{1F251}\u{1F900}-\u{1F9FF}\u{1FA00}-\u{1FA6F}\u{1FA70}-\u{1FAFF}\u{2600}-\u{26FF}]/gu,
    ""
  );

  // 2. RULE 2: Replace em dashes ("—") and en dashes ("–") with clean hyphens or colons
  clean = clean.replace(/[—–]/g, " - ");

  // 3. RULE 3: Convert raw unparsed *word* to clean plain text while keeping **bold**
  clean = clean.replace(/(?<!\*)\*([^\*\n]+?)\*(?!\*)/g, "$1");
  clean = clean.replace(/(?<!\*)\*(?!\*|\s)/g, "");

  // 4. Strip awkward float decimals in currency
  clean = clean.replace(/₹\s*(\d{1,3}(?:,\d{2,3})*)\.\d+/g, (m, p1) => `₹${p1}`);

  return clean;
};
```

## 9. The Anti-AI Slop Checklist

Before declaring any frontend component or view complete, verify every single item on this checklist:

- [ ] **1. No Emoji Clutter**: No emojis in titles, headers, badges, alerts, or AI responses.
- [ ] **2. No Em Dashes**: Zero `—` or `–` characters in copy. Use clean hyphens (`-`) or colons.
- [ ] **3. No Giant Purple Gradients**: Buttons must be solid dark slate (`bg-slate-900 hover:bg-slate-800`) or clean bordered slate (`bg-white border-slate-200 text-slate-700`).
- [ ] **4. Hairline Borders on All Cards**: Every card has `border border-slate-200` and `bg-white`. No borderless floating elements.
- [ ] **5. Number Formatting Consistency**: Numbers use commas, exact currency symbols, and zero float pennies on summaries.
- [ ] **6. Tabular Figures**: Numbers inside comparison tables and ledgers are aligned and formatted uniformly.
- [ ] **7. Single-Row Mobile Headers**: Title and primary action button are flexed on the same row (`flex items-center justify-between gap-2`).
- [ ] **8. 3-Column Mobile Strips**: Complex tables collapse into structured 3-column strips on mobile screens.
- [ ] **9. Touch-Safe Targets**: All interactive buttons have at least 36px height with compact horizontal padding.
- [ ] **10. Low-Opacity Badges**: Badges use light tint backgrounds (`bg-emerald-50 text-emerald-700 border-emerald-200/60`). Never raw, solid neon fills.
- [ ] **11. Unified Max Container**: The entire page is bounded by `max-w-7xl mx-auto px-3 sm:px-6 lg:px-8`.
- [ ] **12. Responsive Chart Overflow**: Chart wrappers use `ResponsiveContainer width="100%"` with fixed aspect heights (`h-48`, `h-64`, `h-68`).
- [ ] **13. Mobile Navigation**: Uses a compact hamburger button and horizontal scroll quick-tabs (`no-scrollbar`).
- [ ] **14. Hydration Safety**: Root `<html suppressHydrationWarning>` and `<body suppressHydrationWarning>` prevent mobile browser frame-token error overlays.
- [ ] **15. High Information Density**: No excessive empty space. Visual weight is concentrated on actionable numbers, progress indicators, and structured ledgers.
