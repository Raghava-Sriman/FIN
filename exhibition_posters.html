PANEL // 02
System Topology: From Raw Documents to Verified Financial Intelligence
Dual-Engine Statement Ingestion & Vault Architecture
1. Table Extraction Engine: FIN's coordinate aligner extracts exact positions for Date, Narration, Ref/UTR, Debit, Credit, and Balance columns across HDFC, ICICI, and Axis PDFs.
2. Regex Stream Engine: Stream formats like SBI NetBanking render as unstructured text lines. FIN matches date anchors (\d{2}/\d{2}/\d{4}) and isolates UPI handles (@okaxis, @ybl).
3. SHA-256 Deduplication Hashing: Transactions on overlapping statement boundaries are hashed (SHA256(Date+Narration+Amount)) to prevent balance skews and duplicate ledger rows.
4. Multi-Tenant Vault Isolation: Every account is partitioned into private directories (vault_storage/users/{user_id}/) preventing data co-mingling.
Solving LLM Latency via Two-Tier Chunked Batching
The Problem: Feeding 234 raw transaction strings directly to an LLM produces 30s+ timeouts, rate limits, and JSON hallucinations.
Tier 1: 99% Rule Filter (<5ms): High-confidence regex rules instantly map known national merchants (Swiggy, Blinkit, Uber, Zomato, Netflix, Amazon) without LLM calls.
Tier 2: Chunked Gemini 3.5 Batching: Ambiguous local merchants (e.g. RAMESH PROVISION) are gathered into batches of 25 with strict Pydantic JSON schemas. This prevents API timeouts and achieves 100% classification coverage.
